# 午市厨房 · 七天连开

需要 Node.js 22 或更新版本。

```sh
npm install
npm run dev
```

类型检查、生产构建与无头逻辑验证：

```sh
npm run typecheck
npm run build
npm run verify
```

Docker 启动：

```sh
docker compose up --build
```

打开 http://localhost:18221 。

## 玩法：七天连续经营

- 一局从固定 180 秒的单日玩法扩展为连续七天，每天有不同的来客节奏、耐心、菜单权重和经营目标（见 `src/shared/catalog.ts` 的 `dayPlans`）。
- 每天先看**营业简报**：说明今日节奏、目标，以及**昨日决策如何影响今日开局**（剩余库存、设备损耗、预购到货、升级就位、目标奖金）。
- 现金、未加工库存、设备等级与损耗**跨日继承**；做熟的菜、备料和灶上食物打烊时一律清零，不能带到明天卖。
- **只有打烊后**才能升级设备、维护灶台或预购次日原料：
  - 升级有 4 小时安装停机时长。选**立即安装**：连夜施工、次日生效，但次日晚开门 30 秒；选**延后安装**：次日保留旧设备能力，后日凌晨自动换装。
  - 灶台损耗随烹饪累积，会压低起锅品质，花维护费可以清零。
  - 预购原料比营业中临时采购便宜，次日开门前自动入库。
- **练习模式**：简报页可反复练习当天，练习在快照副本上运行，收支、库存、设备全部不落地；正式结算只能前进一次。
- **防重复与刷新安全**：结算有阶段 + `settledDay` 双保险，连点“下一天”或刷新都不会重复领取营业款或重复扣采购费；营业中刷新会整局回滚到当天开门前的存档快照。
- 倒闭（日终现金为负）和第七天打烊都有明确的结束界面，并给出完整七天收支表。
- 旧的**单日最佳成绩**继续存放在 `lunch-rush-best`，新的**七天最佳纪录**存放在 `lunch-rush-campaign-best`，两者独立，互不冒充。
